Ad Scraper Test Pages

A set of static pages for testing whether an ad scraper truly intercepts click requests instead of letting them reach the outside world. Each page serves an ad inside a cross-origin sandboxed iframe whose target URL is not in the markup — it is assembled in JavaScript at click time ("JS-secure").

How to use: pick a page by click method below and append your own counter URL as ?target=<your-counter-url> (e.g. a webhook.site URL). Then hand that full link to your scraper. Click activity is logged to the browser DevTools console (prefix [ad-test]) — nothing is shown on the page.

Pages by click-delivery method

Each method produces a different type of network request the scraper must intercept.

  • window-open.html window.open(url) — opens the target in a new tab/popup navigation.
  • anchor.html Programmatic click on a dynamically created <a href> — classic ad click.
  • location.html location.href = url — top-level navigation.
  • beacon.html navigator.sendBeacon(url) — beacon request.
  • image.html new Image().src = url — tracking-pixel GET.
  • fetch.html fetch(url, {mode:'no-cors'}) — fetch request.
  • ping.html <a ping> hyperlink auditing — separate POST (on by default in Chrome/Safari).
  • xhr.html XMLHttpRequest — legacy AJAX, a separate API surface from fetch.
  • script.html dynamic <script src> — how real ad tags load; GET request.
  • iframe.html hidden <iframe src> — document GET (pixels in nested frames).

How the test works

Each click builds a URL containing a unique nonce. If the scraper intercepts the click correctly, no request reaches your counter (the nonce never shows up there). If it leaks, you see a hit with that nonce — proof the request escaped. Without a ?target=, clicks do nothing (a warning is logged to the console).
